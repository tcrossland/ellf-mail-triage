# Facts

Every behaviour of Ellf, its recipes or an LLM service that this template
relies on, with its source and the date it was checked. Anything not checked
is **unverified**.

| explosion/ellf-templates is MIT-licensed. | Its `LICENSE` file | 2026-11-20 |
| A template is one directory with a `README.md` that documents every resource, plus `plans/`, `recipes/`, `config/` and `assets/` as needed, in the layout `/ellf-template` exports. Some also have `scripts/`. | ellf-templates `AGENTS.md` and its tree | 2026-11-20 |
| A template's entry in `templates.json` has `name`, `title`, `description`, `tags`, `counts`, `url`, `author`, `gpu`, `sample_data`, `api_keys`, with tags from a fixed list. | ellf-templates `AGENTS.md` | 2026-11-20 |

| The Solo plan is free for one person with no time limit: one account, a single-user annotation platform and a local cluster. | ellf.ai/pricing | 2026-11-20 |
| `ellf-cli` is proprietary ("All rights reserved"), installed with pip, Python 3.10 or later. Keep it out of this repo's dependencies. | Its PyPI metadata; ellf.ai/docs/install | 2026-11-20 |
| A Solo cluster runs on Linux with K3s, at least 4 GB RAM and 20 GB disk. On a Mac that means a Linux VM; Lima's `k3s` template works. | ellf.ai/docs/cluster#install-local; tried with ellf-cli 24.0.0 | 2026-11-20 |
| `ellf init` and `ellf login --agent claude` install the Ellf skills in the enclosing git repository, found by any `.git` entry above the current folder, and `login --agent` also allows `Bash(ellf kb:*)` in the global Claude Code settings. Run them in a folder that is its own git repository. | Tried with ellf-cli 24.0.0 | 2026-11-20 |
| Ellf's Helm chart installs its own Traefik; K3s's bundled Traefik then fails to install, which does no harm. | Tried with chart ellf-0.1.169 | 2026-11-20 |
| A cluster's address can't carry a port: the chart uses it as the Ingress host. `http://` works only for `localhost` on port 80; any other address needs `https://` and the certificate Ellf issues (`ellf infra tls --trust`), whose CA is limited to the cluster's address and localhost. | Chart ellf-0.1.169 manifest; ellf.ai/docs/cluster#install-local-deploy | 2026-11-20 |
| On macOS, a process without root can bind a port below 1024 only on every interface, so Lima forwards a VM's port 80 to the whole network. A Lima `vzNAT` address with https keeps the cluster on the Mac. | Tried on macOS with Lima 2.3.0 | 2026-11-20 |
| Firefox needs the cluster's CA imported into its own certificate store; Chrome and the macOS keychain share trust. | Tried | 2026-11-20 |
| After `ellf clusters update --address`, the CLI keeps the old address until `ellf login --cluster <name>`, and logging in again can clear the default project (`ellf config project`). | Tried with ellf-cli 24.0.0 | 2026-11-20 |
| `ellf publish data` without a destination stores the file as `<name>-<version>`, without its extension, and a recipe then can't choose a loader. Pass a destination path that keeps the extension, and `--loader jsonl` for JSONL. | Tried with ellf-cli 24.0.0 | 2026-11-20 |
| Existing answers load into a new dataset with the `db_actions` recipe (`--copy.in-asset`), from a JSONL asset with `text`, `label`, `answer` and `_view_id`. | Tried with ellf-recipes on 2026-11-20 | 2026-11-20 |
| A label scheme is an asset of kind `labels`: a JSON object from each label, in order, to its `description`, `do_not_mark` (what not to give it) and `examples` (`text`, with `label` when the label applies). Guidelines are a markdown asset of kind `instructions`. The `textcat` task takes `--label-scheme` and `--settings.instructions`, with `--labels-exclusive` for one label per message; annotators see a label's description on hover. | ellf.ai/docs/assets-files#labels; `ellf tasks create textcat --help` with ellf-recipes on the cluster; helpdesk-routing's README | 2026-11-20 |
| `gemini_agent` and `hf_llm_agent` use the label definitions and instructions of the task they are assigned to, and can add their own scheme and instructions on top. `review` takes a typed `--label` list, or else the labels found in the answers. `train` takes its labels from the answers (`--textcat.train` for exclusive labels) and can draw a learning curve (`--train-curve`). | ellf.ai/docs/assets-files#labels; `ellf agents create`, `ellf tasks create review` and `ellf actions create train --help` | 2026-11-20 |
| `hf_llm_agent` does not run a model on the cluster: it calls a chat model on Hugging Face Inference Providers (by default `meta-llama/Llama-3.3-70B-Instruct`), billed to your Hugging Face token, so the mail goes to Hugging Face and the provider it routes to. No built-in agent runs an LLM on the cluster; `hf_model_agent` (in `ellf-recipes-gpu`) runs a fine-tuned transformers text classifier, not an LLM. | `ellf agents create hf_llm_agent --help` and `hf_model_agent --help`; `ellf recipes list` | 2026-11-20 |

| Gmail's categories are lopsided in a real archive. Of a Gmail account's categorised mail, Personal (Primary) holds 72%, Updates 27%, Forums 0.4%, Promotions 0.3% and Social 3 messages; of a Google Workspace account's, Updates 50%, Forums 22%, Personal 21%, Promotions 7% and Social 1 message. Whether bulk mail sits in Personal or Updates is not checked. | Count-only queries on two real backups | 2026-11-20 |
| Gmail's categories do not stop at 2013, when its tabs launched: in a real Gmail backup, received mail carries a category from October 2010 (a few from July to September 2010) and none before; from then on, mail without one is almost all sent mail or drafts. A second account shows the same from 2010 to 2011. So the slice without Gmail's categories is mail from before late 2010, not before 2013. | Count-only queries per year and month on two real backups | 2026-11-20 |
| A Google Takeout mbox gives each message's Gmail category, in its `X-Gmail-Labels` header: comma-separated labels, a category named like `Category Promotions`, chats labelled `Chat`. The importer accepts this and the `CATEGORY_PROMOTIONS` form. | Third-party guides to Takeout mbox files; no real export checked | **unverified** |
| A Got Your Back backup (db_version 6) keeps each message's labels in the `labels` table of `msg-db.sqlite`, system labels by Gmail ID, so a category is `CATEGORY_PROMOTIONS` and so on; messages are `<year>/<month>/<day>/<gmail_id>.eml`, and chats aren't backed up. In two real Gmail backups all five `CATEGORY_` labels occur, 77% and 89% of messages carry one, almost always exactly one (one message in about 7,500 had two; the importer then takes the first of personal, social, promotions, updates, forums), and none has a chat label. Backups of non-Gmail accounts have no categories. | mailcellar's `backup/gyb.py`, from gyb 1.97's code; count-only queries on four real backups | 2026-11-20 |
